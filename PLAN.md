# PLAN.md — что будет сделано (мини-док)

Полные задания для агентов — в `PROMPT.md` (идеи 1–11). Этот файл — краткая карта: что сделаем, где это будет работать и за счёт чего робот не «сойдёт с ума».

## Три главных принципа

1. **Скорость.** Всё, что работает на Raspberry Pi в реальном времени, переносится в **C++** (новое ядро `UniKostyl/pi_core/` — полная замена `rpi_elp_cam.py`). Ориентир — не медленнее текущего Python-пайплайна: ~26 fps (это потолок камеры), декод ≈23 мс, HSV ≈1 мс, трекинг 3 ворот ≈11 мс. Декодер строго однопоточный (измерено: 4 потока в 3 раза медленнее на этом Pi). На ноутбуке остаётся только pygame-интерфейс — он не на Pi и на скорость матча не влияет.
2. **Оптимизация.** Захват всегда 1920×1080 MJPG (полный FOV) → программный даунскейл 640×360; без аллокаций кадров в цикле; маска + `moments` (никаких `findNonZero`/`boundingRect` — они уже выкинуты как hot spot); морфология и кластеризация — дешёвые; stage-тайминги в логе каждую секунду, чтобы просадку сразу видно было. На Pi будут ещё **тактики** и **обработка датчиков по I2C** — камера не имеет права съедать все ресурсы: бюджет ~1 ядро из 4, без busy-wait, будущие модули добавляются отдельно от горячего цикла.
3. **Отсутствие багов.** Все краевые случаи обработаны явно: hue wrap 0/179, скачок угла 359→1°, обрыв ZMQ/serial, битый JSON, потеря питания (все файлы пишутся атомарно). Ворота «теряются» только после N подряд пустых кадров — гистерезис, чтобы serial не спамил Arduino. Синтетические тесты без камеры (куски ворот + «майка» → слилось в одни ворота, лишнее отброшено). Python- и C++-реализации прогоняются на одних и тех же входах. Честный отчёт: что проверено на железе, что нет.

## Что где будет работать

| Сторона | Язык | Что делает |
|---|---|---|
| Raspberry Pi | **C++** (`pi_core`) | захват камеры, декод, HSV, трекинг 3 ворот, кластеризация, дистанция, граница поля, ZMQ (видео 5555 / цвета 5557 / настройки 5559), serial → Arduino, все файлы-договоры; позже сюда же добавятся тактики и I2C-датчики — отдельными модулями, камера занимает только ~1 ядро |
| Ноутбук | Python (pygame) | UI: калибровка цветов, окно настроек камеры, радар, панели статуса, сохранение цветов |
| Arduino | C (существующая прошивка) | приём `G<id>,<angle>,<area>`, движение; телеметрия обратно — только additive-расширением с согласования |
