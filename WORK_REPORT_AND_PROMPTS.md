4. Компоненты масок кластеризуются, ложные выбросы отбрасываются.

7. Ноутбук публикует настройки камеры на порт `5559`.
8. Pi применяет настройки к UVC-камере и не должен включать автоэкспозицию.

### 4.2. Ложные ворота: лампа и изолента

Корневая причина:

- старый трекер проверял только площадь и расстояние между компонентами;
- не было проверки формы слитого кластера;
- длинная тонкая красная стойка или полоса изоленты могли иметь достаточную площадь и принимались за ворота.

Что сделано:

- в `gate_cluster.py` добавлены параметры:
  - `MAX_CLUSTER_ASPECT = 6.5`;
  - `MIN_CLUSTER_SIDE_FRAC = 0.008`;
- после слияния компонентов и до выбора якоря кластер отбрасывается, если:
  - меньшая сторона меньше минимального порога;
  - отношение большей стороны к меньшей больше 6.5;
- фильтр применяется после слияния, чтобы две половинки настоящих ворот всё ещё могли объединиться;
- аналогичная логика повторена в `pi_core/src/gate_cluster.{hpp,cpp}`.

Добавлены и прогнаны тесты:

- красная папка проходит;
- папка + изолента → выбирается папка;
- папка + лампа → выбирается папка;
- папка + лампа + изолента → выбирается папка;
- только изолента → ворот нет;
- только лампа → ворот нет;
- половина ворот у края кадра проходит;
- две половинки ворот с зазором 13 px сливаются;
- ограничение кандидатов 256 сохраняется;
- stray-компоненты отбрасываются.

Проверка:

- `out/false_gate_check.py` — pass;
- `out/cluster_check.py` — pass;
- C++ `pi_core_tests_direct.exe` — 540 проверок, 0 ошибок;
- `out/parity_check5.py` — 61 кадр, Python/C++ bit-exact parity OK.

Ограничение:

- проверка выполнена на синтетических сценах и сохранённых кадрах, не на полном живом сценарии с лампой и изолентой одновременно.

### 4.3. Закрытие радара по системному крестику

Корневая причина:

- цикл окна OpenCV реагировал только на `ESC`;
- нажатие системного крестика закрывало окно, но внутренний флаг `_win_open` оставался `True`;
- код продолжал считать окно открытым.

Что сделано:

- после `waitKey(1)` проверяется `cv2.getWindowProperty(..., WND_PROP_VISIBLE)`;
- если видимость `< 0.5`, окно считается закрытым;
- состояние сбрасывается, окно уничтожается;
- обрабатывается `cv2.error`;
- pygame-радар больше не рисует дуги для незаконфигурированных ворот или `angle is None`.

Проверка:

- `out/radar_check.py` — pass;
- закрытие по крестику проверено через mock `getWindowProperty`, не реальным кликом мыши.

## 5. Native C++ проект

### 5.1. Причина переписывания

Старый проект доказал функциональность, но имел ограничения:

- Python-цикл на ноутбуке и Pi;
- несколько независимых реализаций одной логики;
- риск расхождения Python и C++;
- сложность оптимизации UI и захвата одновременно;
- отсутствие единого контракта конфигурации;
- часть ошибок возникала на стыке Python-модулей.

Решение:

- новый C++-репозиторий;
- общий core для ноутбука и Pi;
- SDL2 + Dear ImGui для UI;
- OpenCV для зрения;
- ZeroMQ для обмена;
- строгие unit/parity-тесты;
- отдельные CMake-профили Windows/Pi;
- Pi можно проверять временно, не перезаписывая калибровки.
